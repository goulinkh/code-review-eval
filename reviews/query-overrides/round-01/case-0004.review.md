**Defect: overrides are appended instead of replacing existing values** (`src/request_url.py`, head lines 13–15)

The loop appends `(key, value)` to `fields` and never removes the existing entries for that key. This contradicts the contract that a non-None override replaces all values for its key.

Triggering input: `request_url("https://x/c?sort=name&sort=date", {"sort": "price"})`.

The result is `?sort=name&sort=date&sort=price`. The catalogue endpoint reads the first occurrence of singleton fields such as `sort`, so it still sees `name` and the override has no effect.

The same happens with a single existing value, e.g. `?sort=name` with `{"sort": "price"}` gives `sort=name&sort=price`. An empty-string override (`{"sort": ""}`) is also appended after the old values, so it is ignored too.

Fix: for each non-None override, drop all existing fields with that key, then add the new value. To keep the key's position, replace the first occurrence and remove the rest. Either way, build a new list and don't mutate the inputs. For example:

```python
active = {k: v for k, v in (overrides or {}).items() if v is not None}
fields = [(k, v) for k, v in fields if k not in active]
fields.extend(active.items())
```

The `None` handling is correct: it neither adds a missing key nor changes existing values. Input mutation and preservation of non-query URL components also look fine.
